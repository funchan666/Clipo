## 用户反馈后的增量处理

用户确认：继续检查原 API 地址；需要无广告奖励和开屏广告；只用 `2DhdI8` 测试，不再索要其他平台样例；协议占位暂不处理。

- 再次请求 HTTPS 仍在握手阶段失败。改用 Google 和 Cloudflare 两个独立 DoH 查询 A 记录，均返回 `Status: 3`（NXDOMAIN），权威区为 `io-d.cc`。这比本机代理 198.18 地址更有辨识力：当前公共解析没有 `devapi.io-d.cc` 记录；尚待确认是否存在专用 DNS 或地址差异。
- 已加入 SDK 明确 no-fill 时的幸运奖励：发当前阶段观看／收藏奖励，不推进真实广告完成次数，不解锁无限观看；第 4 阶段仍发第 3 档奖励。重复请求 ID 不重复发放，暂定 60 秒领取间隔；仅 SDK 的 no-fill 适用，断网、超时、配置／同意／展示错误不发奖。奖励成功持久化后才显示复用原创插画的弹窗动画。
- 已加入冷启动开屏广告：正式配置取 adType=1，测试配置强制 Google 官方示例单元；仅已有登录会话时尝试，启动页总计最多等待广告机会 3 秒（另有原本 0.75 秒启动过渡），超时跳过，晚到结果不弹窗，不自动登录。正式模式须确认权益且非会员，并满足 UMP 许可；冷启动不强行打开 UMP 表单。关闭或展示失败后继续进入应用。热启动／后台返回不重复展示。
- 新版 Debug 模拟器编译通过，日志 `ads-build.log`；额度测试直接编译生产 QuotaStore，使用测试专用内存存储替身，检查阶段、重复请求／回调、账号归属、60 秒间隔、第四次无限、持久化重建、保存失败和旧账本兼容，全部通过。未把测试替身加入应用 target。
- Mac 仍锁屏：没有完成新版预览、广告弹窗、第四次真实广告结果及退出流程的点击复测。幸运奖励是逻辑测试，并非真实 no-fill 广告观察；开屏广告只有构建证据，没有显示成功证据。
- 下文“尚未实现无广告奖励／开屏广告”为首次审查历史结论，现以本节为准。支付契约仍需后端补充；政策占位按用户要求暂不修改。

官方 SDK 依据：[开屏广告](https://developers.google.com/admob/ios/app-open)、[广告加载错误](https://developers.google.com/admob/ios/ad-load-errors)，并核对已安装 GoogleMobileAds 13.11.0 头文件。

## 结论

应用已实际编译、安装、启动并点击测试。五个 Tab、本地导入和视频／音频导出、官方测试激励广告前三次奖励、协议 WebView 已验证。短码 `2DhdI8` 实际提交后遇到 TLS 连接失败，未取得业务响应，不能判定短码是否有效，也不能宣称在线播放已通过。

测试期间 Mac 锁屏，电脑控制工具无法继续点击。第四次广告结果和本轮新修复的预览播放尚待解锁后复测。

## 本轮已处理

1. 编辑预览改为先生成最高 720p 的临时 MP4 再播放，避开此次直接播放视频合成失败；增加准备状态、防重复操作、取消与临时文件清理，并显示播放器错误。导出仍按用户的质量配置执行。
2. App Store 无商品或加载失败时，不再一直显示“Plans are loading”；区分请求中和空结果，提供重试，说明在线购买暂不可用。
3. TLS、离线和超时错误转换为可理解的提示；Debug 日志只记录路径和错误码，不记录 token、密码、请求参数或响应正文。
4. 已无限观看时，广告入口改为说明增加收藏额度，不再诱导为增加观看次数。
5. 发布配置 `lang` 使用应用本地化语言，而非设备首选语言。
6. 按文档兼容文件夹数量位于 `extraInfo.childrenFileNum` 的结构，优先使用顶层数值。
7. 为数据契约增加独立回归检查，覆盖数值／数字字符串／null、非法值、文件夹过滤、嵌套数量、URL scheme 和权益时间戳。实际运行通过。

最终 Debug 构建成功；只有未使用 AppIntents 的元数据提取提示，没有 Swift 编译错误。新修复的运行验证被锁屏阻断，不能用构建成功替代。

## 短码阻塞的证据与边界

- Mac curl 请求相同 HTTPS 主域名也在握手阶段失败，未取得 HTTP 状态。
- 系统启用了本机 127.0.0.1:1082 代理，域名解析为 198.18.0.131；这属于当前本机代理解析路径的观察，不是源站真实 IP 的认定。
- 经当前代理尝试也失败。仅凭这些证据无法区分代理节点问题、域名配置还是源站链路问题。
- 未关闭 TLS 校验、未修改用户代理设置、未偷偷替换 API 主域名。
- 需要确认测试域名仍可用，并在可连接网络上重新验证登录、`2DhdI8`、内容列表和播放。

## 需要确认或补充的事项

1. **API 可用网络／主域名**：当前 HTTPS 无法建立。需要后端或网络环境恢复后，才能完成短码和在线核心功能验证。
2. **支付取消、失败上报**：文档支持 `canceled`、`error`，当前仅本地标记放弃并结束失败交易。取消时可能没有 transactionId 或收据，文档没有说明这些字段是否可空、重试与幂等规则。需要提供这两种请求的真实示例后补齐，不能伪造交易号或成功收据。
3. **跨安装恢复购买**：现有恢复依赖原订单本地映射。缺少映射时保留交易并提示核对，不按当前用户或 SKU 猜测归属。后端需提供 Apple originalTransactionId → 原订单／账号的恢复契约，以及重复确认的幂等保证。
4. **删除账号**：按此前明确要求暂为模拟，本地重置并退出；未删除服务器数据。正式账号删除需要后端接口，不能把此模拟流程当成真实注销。
5. **广告无填充的“幸运奖励”**：文档要求但当前未实现。需要明确每阶段次数上限、防连续点击领取、额度与服务器是否同步；现在无广告只显示错误，不虚构看完广告。开屏广告 adType=1 也未实现。激励 adType=2、第 4 次无限观看已按此前确认保留，不需要重复确认。
6. **平台支持范围**：首页展示 12 个热门平台。它们是展示和操作引导，并不能证明后端逐个平台解析成功；需要代表性链接验证，尤其含完整分享文本／多个链接／密码的情况。
7. **登录 uniqueId**：文档允许获取失败为空，当前直接为空，没有向第三方查询公网 IP。如果后端统计或风控依赖 IP，应明确是否由后端读取请求 IP，还是客户端必须尝试外部 IP 服务。
8. **价格配置**：两商品 ID 已是 16 位字母。usdPrice 暂为月 999、年 9999；文档示例为 999／9999，但只写“美元价格或方案价格”，未明确是美分还是方案编码，需要后端明确单位并与最终登记价格一致。Apple 商品登记后还需真机或合适 Sandbox 环境完成购买、取消、恢复、续订及断网重试，不能保证目前支付已验证。
9. **协议占位**：两个公开网页仍有 `your-email@example.com`、`Month Day, Year`、`Your legal name or company name`。需要替换实际联系邮箱、日期和主体，并与真实数据处理和删除能力一致。
10. **安全区域含义**：当前背景和视频铺满屏幕；按钮、输入框和 TabBar 保留对刘海／Home 指示条的避让。如果要求连这些可点击控件也伸入遮挡区，需要明确具体效果。尚未验证 Duo 折叠／内外屏切换。
11. **额度可信来源**：文档没有服务端扣减与激励验收接口，当前按用户在本机 Keychain 记账。跨设备同步、改时钟后的服务端一致性不在当前契约内。
